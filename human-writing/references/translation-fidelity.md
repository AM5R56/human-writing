# 翻译保真模式

按用户指定的底本与译法工作。把 `translation` 作为独立校订路线；不要加载或执行 `forum-prose.md`、`fiction.md`、`formats.md`、`reality.md`、`revision.md` 的创作步骤。即使这些文件已在上下文中，也只执行本文件的翻译规则。默认 `creative` 路线保持不变。

## 对照校订流程

1. 固定底本、版本和章节，读取原文、润色前中文和项目术语表。保留不可变的基线副本。没有原文时，只作暂定建议并标明缺少对照依据，不补写、不删改、不声称已完成保真校订。
2. 保留原段号及顺序，一段原文对应一段译文；标题、表格、附录、图注和注释也建立独立对应关系。对照版保留英文原段及原图位置。不要为了检查器改动原书段号；本检查器格式不适用时，另作可回溯映射或人工对照。
3. 先标明该段的事实、否定、对比、因果、条件、让步、推测强度、评价主体、修辞、引语与注号。保留原作者的重复、歧义、时代立场和不确定性，不把推测变成定论，不把先后补成因果。
4. 仅改可由原文支持的误译、指代、搭配和中文语序。不要因为句式禁令、连词密度、句长、材料数量、结尾、比喻或“信息量低”删改原文。拆句也要保留限定范围和逻辑关系；不要为凑自然感新增例子、对白、动机、事实核验口吻或背景。
5. 优先采用项目核准译名；同一概念跨章节一致，不为避免重复换同义词。不同词义可分条并记录适用范围；不要把某一本书的犯罪黑话映射当成所有书的通用词典。首次括注原文、后续用译名等要求以项目规则为准。发现既有术语可能有误时，提交证据和建议，不静默重命名。
6. 保留直接引语、嵌套引语、原文引文与史料对白的范围、说话者、信息和修辞，不改为转述，不省略敏感或陌生内容。引语翻译本身有误时，单列原文和建议译法请求核准，不把修改后的引语当作已通过。不得暗中纠正原作者事实错误；另列译注或疑问，不能冒充原文。
7. 保留原注号、位置、图表、货币、单位、时间及专名。尾注中“引文照原文、解释译出”等项目规则优先。未经授权不得删页、删段、并段或调整章节顺序。需要现代标点转换时记录变化与理由，不能机械清零冒号和破折号。
8. 输出候选译文以及独立的逐段修改记录，记录原文、旧译、新译、改动理由及待确认点。对每一处变化人工检查有无新增、遗漏、概念漂移、语气变化和引语变化；无法确定时保留旧译并标疑。即使用户只要正文，也不把未复核候选当作正式稿；可把记录放在独立文件。机械检查通过不能代替人工双语复核。

## 只读检查器的输入

原有 `python3 scripts/check_prose.py 稿件.md` 仍执行创作检查。

翻译模式必须提供三个独立文件：候选中文、不可变的润色前中文、JSON 对齐清单。两个中文文件都以行首 `【原段号】` 开段，不允许无段号前言、空段或重复段号。段内可换行，可包含图表和原文引文。原文中恰有同样的行首标记时不能直接套用该输入格式，应先建立无歧义映射；不要偷偷改正文来满足解析器。

```text
【0185】他不是卖锯末，而是以假钞招徕买家。[1]
【0191】他说：“这是暗板局——把包换掉。”
```

对应 JSON 的完整最小结构如下。例句为自拟测试句，不是原书摘录；哈希必须替换为基线文件实际字节的 SHA-256。

```json
{
  "version": 1,
  "baseline_sha256": "替换为64位小写SHA-256",
  "units": [
    {"id": "0185", "source": "He did not sell sawdust; he lured buyers with counterfeit notes.", "protected": ["[1]"]},
    {"id": "0191", "source": "He said, ‘This is the panel game—switch the bag.’", "locked": true}
  ],
  "glossary": [
    {"source": ["panel game"], "target": "暗板局", "forbidden": ["面板游戏"]}
  ]
}
```

运行前由人工依据已确认底本建立和校对清单，不允许为让检查通过而修改原文、基线、哈希或删除术语规则。原文保存在清单中是对齐依据，不代表脚本已认证其出处。

```bash
python3 -c 'import hashlib,pathlib; print(hashlib.sha256(pathlib.Path("润色前译文.md").read_bytes()).hexdigest())'
python3 scripts/check_prose.py 候选译文.md --mode translation --baseline 润色前译文.md --manifest 对齐清单.json --json
```

检查覆盖以下内容：

- 对齐段号的新增、遗漏、重排及重复；基线哈希；输入字段与重复 JSON 字段。
- 每段所有文字变化，输出原文、旧译、新译与统一差异。任何变化均返回 `review_required` 或 `blocked`，不自动放行。
- 基线中的中文弯引号、直角引号和英文双引号，包括嵌套、跨行引语，以及 Markdown `>` 引文。引语作为整体逐字锁定；未配对的基线引号是输入错误。未配对的候选引号是违规。英文单引号可能是撇号，不自动配对，须通过 `protected` 或整段 `locked` 指定。
- 每段 `[数字]` 注号、阿拉伯数字及 Markdown 图片的内容和顺序；段内其他移动仍由差异复核发现。HTML/引用式图片、表格、单位、中文数字和首次括注等可整段锁定或显式保护，不声称自动覆盖所有格式。
- `protected` 指定文本的出现次数和 `locked` 整段完全一致。相同保护文本在段内移动不能靠次数识别，必须看差异。要求位置绝对不变时锁定整段。
- 对清单声明的英文术语，忽略大小写并检查词界，核对中文译名存在与基线出现次数是否变化，检测声明的禁译词。词形变化需明确列入 source 别名，多个词义应按适用章节分别维护清单。检查器不能识别全部同义替换或理解词义。

退出码 `0` 只表示未发现变化且机械约束通过；`1` 表示机械违规或任何候选变化待人工复核；`2` 表示缺输入、格式损坏或基线错版。JSON 的 `status` 区分 `unchanged`、`review_required`、`blocked` 和 `input_error`。不把 `0` 解读为译文忠实性认证。脚本不写回、不自动修复，也不通过风格白名单掩盖语义删除。

## 项目术语的示例

下表仅供配置已核准采用这些译名的项目，不作为跨书自动替换规则。

| 原文 | 核准译名示例 | 禁止混淆 |
| --- | --- | --- |
| sawdust man / sawdust swindler | 假钞骗子 | 不能因词面锯末译成锯末工，也不等于假金砖骗子 |
| panel game | 暗板局 | 不能泛化成普通赌博或面板游戏 |
| panel thief | 暗板贼 | 与骗局名称分开 |
| gold brick / gold-brick swindle | 假金砖 / 假金砖骗局 | 与假钞骗局分开，分别配置 |
| green goods | 绿货（假钞） | 首次括注规则由项目约定；后文可配置为绿货 |
| counterfeiter | 伪钞制造者 / 造假者 | 根据语境选定，不任意混用 |
